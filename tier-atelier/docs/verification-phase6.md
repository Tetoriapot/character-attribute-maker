# フェーズ6 検証記録

検証日：2026年10月28日。Windows、Node.js 24.19.0、pnpm 11.25.0、Playwright 1.64.1付属Chromiumを使用しました。PCは1440×1080、スマートフォンはChromiumのiPhone 13エミュレーションです。テスト用の独立したプロファイルを使い、利用者の保存データは使用していません。

## 実装と修正

vite-plugin-pwa 2.0.0とWorkbox 7.4.1で、Manifest、アイコン、静的ファイルの事前キャッシュを追加しました。画像出力画面の遅延読み込みファイルもキャッシュし、オフラインで初めて開く場合にも対応しています。画像とプロジェクトの保存形式は変更していません。

準備状態・オフライン表示・インストール案内・更新通知・手動確認を追加しました。更新時は未適用入力、処理中の操作、別タブを検査します。確定済みの変更をIndexedDBへ保存してから更新し、保存失敗時は画面とデータを保持します。

検証中に、固定表示の更新通知がスマートフォンのバックアップボタンに重なる問題を修正しました。通知をツールバー内へ移し、更新を延期した状態でも通常の操作を続けられることを確認しています。キャッシュ整理は配置先自身のキャッシュに限定し、ルートとサブディレクトリのアプリを併設しても互いのキャッシュを消さないようにしました。起動時は既存のService Worker登録も確認します。

## 実行結果

| 確認 | 結果 |
| --- | --- |
| `pnpm typecheck` | アプリ・テスト・Service Workerとも成功 |

| `pnpm test:e2e --workers=2` | 89件成功、端末別の7件スキップ |
| `pnpm test:pwa` | 16件成功、端末別の2件スキップ |

| ロックファイル | `--frozen-lockfile --offline --ignore-scripts`で再現性を確認 |
| 本番preview | 画像登録・デザイン・自動保存・JSON復元・3形式の画像出力・印刷・レスポンシブ確認が成功 |

通常の回帰テストには、Tier・アイテムの作成・編集・削除・複製・移動・ロック、プロジェクト管理、24枚の画像登録、切り抜き・背景・全テンプレート、保存失敗・別タブ競合・不正ファイル・旧JSON、画像出力・印刷・共有、Undo・Redo・検索・タグ・一括操作・仮想トレイ・キーボード・タッチ操作を含めています。320〜1920pxの表示確認とaxeによる検査も実行しました。

PWAテストではルートと`/nested/tier-atelier/`へ同じ本番ビルドを配信しました。24枚の画像を保存して通信を切り、再読み込み、追加登録、Undo・Redo、デザイン保存、PNG・JPEG・WebP出力、画像込みJSON復元を実行しました。画像出力画面はオフラインになってから初めて開いています。新しいタブ、クエリ付きURLでも起動し、復元画像の元バイトと対応する参照を確認しました。

別のテストでは、同じプロファイルを使ってChromiumのプロセスを完全に終了・再起動しました。オフラインで24枚の画像を読み込み、追加登録・Undo・Redo・保存が成功しています。Windowsの長いパスでCacheStorageの初期化に失敗したため、テスト専用プロファイルは短いパスを使用しています。

更新は本番ビルドA・Bを切り替えて確認しました。通知の延期、別タブによる中止、未適用入力による無効化、保存容量エラー時の緊急バックアップと再試行、更新後のデータ一致を検証しています。新版のHTMLに503を返してキャッシュを失敗させた場合も、旧版でオフライン編集を続け、配信復旧後に更新できました。初回登録失敗からの再試行とインストールイベントのキャンセル・完了も検証しています。

PWAの設定・更新画面でaxeの違反はなく、アプリの未処理例外・コンソールエラーもありませんでした。出力PNGを目視し、編集ボタン、通知、選択枠などが入っていないことを確認しています。透過・寸法・日本語ファイル名は出力ファイルをデコードして検証しました。

PWAのスキップ2件は、モーダルのプロパティ画面を開くモバイルでの未適用入力とPWA画面の同時表示、およびPCで実施するプロセス再起動テストのモバイル重複です。通常の7件はマウス・タッチなど端末別の操作テストです。
