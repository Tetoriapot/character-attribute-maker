# フェーズ2の検証記録

実施日：2026年10月27日

## 実装と確認範囲

画像の一括登録・サムネイル・画像を共有するアイテム複製、プロジェクト管理、DexieによるIndexedDB自動保存、画像を含むJSONバックアップと復元を追加しました。元画像とサムネイルはBlobとして保存し、プロジェクトのメタデータと分離しています。

PC版ChromiumとiPhone 13相当のChromiumで画像24枚を登録し、移動・メタデータ編集・複製後の25アイテムを再読み込みできました。画像21枚のJSON往復テストでは、元画像のバイト列、Tier配置、名前・説明・タグが一致しました。復元後のプロジェクトIDとBlobキーは新しく発行し、元のプロジェクトを残しています。

## データ保護と異常系

保存中に追加した編集が次の保存へ引き継がれること、別タブによる更新を古いタブが上書きしないことを確認しました。容量不足を再現したテストでは、プロジェクトとBlobの書き込みが一括で取り消され、画面に残った画像からバックアップできました。再試行後は保存して再読み込みできます。

起動時にIndexedDBを開けなかった後の再試行で、Dexieが以前のエラーを返し続ける問題を修正しました。明示的に接続を開き直し、再試行後も保存済みプロジェクトが残ることを確認しています。

空・破損・容量超過・寸法超過・拡張子不一致・MIME不一致の画像、不正JSON、欠損フィールド、重複ID、不正な配置、画像欠損、不正Base64、寸法の不一致、未対応schemaVersionを検証しました。日本語と空白を含むファイル名も確認しています。複数メガバイトのBase64を、正規表現の再帰で失敗せず復元できることも単体テストに含めました。

プロジェクト削除のキャンセル、最後のプロジェクト削除後の空プロジェクト作成、複製プロジェクトで共有する画像の保持も確認しました。容量不足とファイルサイズ境界はテスト内で再現しており、端末のディスクを実際に使い切ってはいません。

## 既存機能と画面

フェーズ1のTier追加・改名・色変更・順序変更・複製・削除・ロック・折りたたみ、文字アイテムの編集・配置・削除、マウス・キーボード・長押しドラッグを回帰テストの対象にしています。ダイアログのフォーカス管理、未適用の入力がある場合の離脱確認、320〜1920px幅の表示も含めています。

初期画面、Tier設定、文字追加、画像追加、プロジェクト一覧のaxe検査で、WCAG 2 A/AA・WCAG 2.1 AAの違反はありませんでした。各ブラウザテストでコンソールエラーと未処理例外がないことも確認しました。PC・スマートフォンの画像一覧とプロジェクト一覧をスクリーンショットで確認しました。

## 制限と残件

JavaScriptのチャンクは約577kB、gzipで約180kBです。ビルドは成功していますが、Viteの500kB警告が残っています。公開前の読み込み性能の確認対象とします。

iPhone・Android実機、Safari・Firefox、実際のスクリーンリーダーは未確認です。PWA・オフライン編集、デザインテーマ、画像出力、Undo・Redoは後続フェーズの要件です。
