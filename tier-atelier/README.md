# TIER ATELIER

PCとスマートフォンでTier表を作成する、ブラウザ内で動作するWebアプリです。フェーズ3まで実装しています。

## 現在使える機能

Tierの追加・削除・複製・改名・背景色と文字色の変更・並べ替え・ロック・折りたたみに対応しています。文字アイテムを作成し、名前・説明・タグを編集できます。アイテムはドラッグ、移動先の選択、前後ボタンで配置できます。

PCでは3カラムと左右パネルの表示切替、スマートフォンでは下部ツールバーと設定ドロワーを使用します。日本語UI、キーボード操作、ダイアログのフォーカス管理、エラー表示に対応しています。

画像の一括登録、画像を共有するアイテム複製、プロジェクトの作成・一覧・切り替え・複製・削除にも対応しています。確定した編集内容と画像は、このブラウザのIndexedDBへ自動保存します。再読み込みすると、前回開いていたプロジェクトを読み込みます。

画像を含むJSONバックアップと復元ができます。背景・文字・カードのデザイン編集とテンプレートにも対応しています。画像出力、Undo・Redo、PWA・オフライン対応を含む残りの要件は[TASKS.md](TASKS.md)に記録しています。

## 起動

Node.js 22.12以上の偶数メジャー版とpnpmを使用します。開発時の検証環境はNode.js 24.19.0、pnpm 11.25.0です。

```powershell
cd C:\Projects\相関図ツール\tier-atelier
pnpm install --frozen-lockfile
pnpm dev
```

ターミナルに表示されるローカルURLを開いてください。ファイルを直接ダブルクリックして起動する構成ではありません。

## 基本操作

1. 「画像を追加」でファイルを複数選択するか、「文字を追加」で名前を入力して「追加する」を押します。新しいアイテムは未分類に入ります。
2. アイテムを選び、「移動先」を選択して「移動する」を押します。ドラッグハンドルからも移動できます。
3. ランク名を選ぶと設定が開きます。名前と色を入力し、「変更を適用」を押します。色はカラーピッカーとカラーコードのどちらでも指定できます。
4. ランクやアイテムの順序は上下・前後ボタンで変えます。ドラッグでも並べ替えられます。

スマートフォンではタップして設定ドロワーを開きます。ドラッグハンドルを約300ミリ秒長押しするとドラッグを開始できます。スクロールはハンドル以外の場所から操作してください。

キーボードではTabで対象を選び、Enterで実行します。ドラッグハンドルではSpaceで開始し、矢印キーで移動、Spaceで確定、Escapeでキャンセルします。移動先の選択と上下ボタンもキーボードで操作できます。ダイアログはEscapeまたは「閉じる」で閉じます。

ランクを削除すると、そのランクのアイテムを順序どおり未分類の末尾へ移します。ランクの複製では名前・配色・設定をコピーし、アイテムは複製しません。ロックしたランクは改名・配色変更・直接の並べ替え・削除と、所属アイテムの編集・移動を制限します。別のランクの追加や並べ替えによって表示位置がずれることはあります。

入力欄の変更は「変更を適用」で確定します。未適用の入力がある状態で別のランクやアイテムを選ぶときと、プロジェクトを切り替える前に、入力を破棄するか確認します。追加フォームや設定ドロワーを閉じると未適用の入力は破棄します。画面上部の使い方にも主要操作を記載しています。

## 画像の登録

PNG・JPEG・WebP・GIFに対応しています。ファイル選択、画面へのファイルのドロップ、画像の貼り付けが使えます。入力欄への通常の貼り付けは、文字入力として扱います。GIFは最初のフレームを静止画として表示し、元ファイルも保持します。

上限は1枚20MiB、一辺8,192px、32メガピクセルです。1回の登録は100枚・合計100MiBまで、1プロジェクトの元画像は合計128MiBまでです。MiBは1,048,576バイトです。拡張子・MIME・実データを照合し、画像としてデコードできることも確認します。複数画像の中に不正なファイルがあれば、そのファイル名と理由を表示し、正常な画像だけ登録します。

表示用サムネイルは縦横比を保ち、長辺160px以内で作成します。アイテムを複製しても元画像は複製しません。最後の参照を削除した画像は、ほかのプロジェクトからも参照されていなければ保存先から削除します。

## 保存・プロジェクト・バックアップ

画面上部に「保存中…」「保存済み」「保存できませんでした」を表示します。保存が失敗した場合も編集内容は画面に残し、再試行とJSONバックアップを案内します。保存していない変更、未適用の入力、処理中の操作がある場合は離脱時に確認します。OSやモバイルブラウザによる終了時には確認を表示できない場合があります。

「プロジェクト一覧」から作成・切り替え・複製・削除を行います。切り替える前に現在の編集を保存します。最後のプロジェクトを削除すると、空の新しいTier表を作成します。別タブで同じプロジェクトが変更された場合は、上書きせず保存を停止します。その場合は現在の編集をバックアップしてから再読み込みしてください。

「JSONバックアップ」は、現在の確定済みの編集と元画像を1つの`.tier.json`ファイルへ保存します。保存失敗中でも実行できます。「JSONから復元」でそのファイルを選ぶと、内容を検証して新しいプロジェクトとして保存します。既存プロジェクトは上書きしません。JSONファイルの上限は256MiBです。

保存先はブラウザ・プロファイル・サイトのオリジンごとに異なります。開発用とpreview用のポートが異なる場合も保存先は別です。ブラウザのデータ削除やプライベートブラウズの終了で保存内容が消えることがあるため、必要なプロジェクトはJSONバックアップを保存してください。

## デザイン編集

PCでは左側、スマートフォンでは下部バーの「デザイン」を開きます。背景を単色・グラデーション・パターン・画像から選び、文字、見出し、ラベル幅、画像サイズ、余白、角丸、枠、影を設定できます。「デザインを保存」で適用すると、自動保存が始まります。ランクごとの最小高さとラベル幅は、ランク設定から変更します。

テンプレートはクラシック・ミニマル・ゲームUI・レトロ・ポップ・サイバー・ゴシック・和風の8種類です。「全体」「ランクのみ」「画像カードのみ」から適用範囲を選び、「テーマを適用」を押します。ランク配色は別に3種類あります。Tier名・ID・並び順・アイテム・配置は保持し、ロック中のTierの色は変えません。配色数よりTierが多い場合は、上から順に色を繰り返します。

「背景画像を登録」は選択後すぐに適用・保存します。画像登録と同じ形式・寸法・容量制限を使い、プロジェクトの画像合計128MiBに含めます。テーマ適用などで背景の種類を切り替えても、登録済みの背景画像は保持します。「画像」に戻すと再表示でき、「背景画像を削除」で参照を解除できます。

画像アイテムの設定では、左端・上端・幅・高さを元画像に対する割合で入力してトリミングできます。元画像は変更せず、切り抜き範囲を保存します。JPEGはEXIFの向きを反映し、GIFの画像カードは最初のフレームを表示します。背景画像には元ファイルを表示するため、アニメーションGIFは再生されます。

デザイン設定、背景画像、トリミングはプロジェクト複製とJSONバックアップにも含まれます。フェーズ2のJSONも読み込めます。フォントは端末にある書体を使用するため、端末によって見た目が異なります。狭い画面ではラベル幅・画像サイズ・余白を表示幅に合わせて縮め、保存値は維持します。

## 検証とビルド

```powershell
pnpm typecheck
pnpm lint
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e --workers=2
pnpm build
pnpm preview
```

Playwright用Chromiumがインストール済みなら、ブラウザのインストールは不要です。ブラウザテストは専用ポート4178でViteを起動します。テストはユーザーのブラウザプロファイルや既存データを使用しません。

`pnpm build`で生成される`dist/`を静的サーバーで配信できます。`base: './'`を指定しているため、サブディレクトリへの配置に対応します。現段階では公開処理とService Workerを追加していません。既存のキャラ属性メーカー用の公開ワークフローは変更していません。

## データと拡張

プロジェクト、Tier、アイテムにはUUIDを使用します。Tierの順序は`tiers`、アイテムの順序は各Tierの`itemIds`と`unrankedItemIds`で管理します。配置変更は一括更新し、同じアイテムが複数箇所に所属しないようにしています。

画像素材は`blobKey`で参照し、元画像とサムネイルのBlobをプロジェクトとは別のテーブルに保存します。日本語文言は`src/app/messages.ts`、`src/app/storageMessages.ts`、`src/app/designMessages.ts`にまとめています。保存形式の詳細は[DATA_SCHEMA.md](DATA_SCHEMA.md)、設計方針は[docs/development-plan.md](docs/development-plan.md)を参照してください。

テーマは`src/data/themes/themes.json`、ランク配色は同じディレクトリの`ranks.json`で管理します。配列に固有の`id`、表示名、配色、必要なスタイルを追加すると選択肢に反映されます。テーマの省略項目は`features/design/settings.ts`の既定値を使い、読み込み時にZodで検証します。

```text
tier-atelier/
├─ public/                 ローカルの静的ファイル
├─ src/
│  ├─ app/                 画面全体・文言・エラー境界
│  ├─ components/          Tier表・サイドバー・フォーム・ダイアログ
│  ├─ data/                型・初期値・Zod検証・マイグレーション・Dexie
│  ├─ features/editor/     編集コマンドとドラッグ処理
│  ├─ features/design/     デザイン既定値・テーマ検証・表示用スタイル
│  ├─ features/assets/     画像検証とサムネイル生成
│  ├─ features/backup/     画像を含むJSON入出力
│  ├─ features/storage/    自動保存とプロジェクト操作
│  ├─ stores/              Zustand状態管理
│  └─ styles/              共通スタイルとレスポンシブ表示
├─ tests/unit/             編集・保存・検証・入出力の単体テスト
├─ tests/e2e/              Playwrightブラウザテスト
├─ docs/                   開発計画・企画書原文・検証記録
├─ DATA_SCHEMA.md
├─ TEST_CASES.md
└─ TASKS.md
```

ログイン、バックエンド、解析タグ、画像の外部送信はありません。外部フォントやCDNにも依存しません。通常のページ配信に伴う通信以外に、編集データを送信する処理は実装していません。
