# 検証項目

## フェーズ1

単体テストは`tests/unit/editor.test.ts`、画面操作は`tests/e2e/editor.spec.ts`で確認します。

| 対象 | 期待結果 |
| --- | --- |
| 初期状態 | S〜Dの5ランク、空の未分類、UUID、schemaVersion 1 |
| Tier追加 | 指定位置に挿入し、既存TierのIDとデータを維持 |
| Tier編集 | 名前・背景色・文字色を適用、空白名と不正色を拒否 |
| Tier複製 | 設定を複製し、所属アイテムを重複させない |
| Tier削除 | 確認後に削除し、所属アイテムを未分類へ退避 |
| 全Tier削除 | 空状態を表示し、新しいTierを追加できる |
| 並べ替え | 上下ボタン、ドラッグ、キーボードで順序を変更 |
| ロック | 対象Tierの編集・移動・削除と、所属アイテムの編集・出入りを拒否 |
| 文字アイテム | 作成、名前・説明・タグ編集、重複タグ除去、確認付き削除 |
| アイテム配置 | Tier間、未分類、同じTier内で重複・欠落なく移動 |
| ドラッグ | ドロップ時のみ確定、Escapeでキャンセル、タッチは長押し |
| 異常操作 | 存在しないID、不正な移動先、非有限の順序値を拒否し元データを保持 |
| 入力保護 | HTML文字列をテキスト表示し、スクリプトを実行しない |
| モーダル | 開く時・閉じる時のフォーカス管理、Tab循環、Escapeで閉じる |
| 離脱確認 | 未適用の入力がある状態で閉じると確認し、キャンセルすると内容を保持 |
| レスポンシブ | 320・390・768・1024・1280・1920pxで意図しない横スクロールなし |
| アクセシビリティ | 初期画面・Tier設定・文字追加画面をaxeのWCAG A/AAで検査 |
| コンソール | 各ブラウザテストでerrorと未処理例外がない |

25アイテムを200回移動する単体テストで、配置の一意性を確認します。スマートフォンのタップと長押しはPlaywrightのChromiumエミュレーションで確認します。実機のiPhone・Android、支援技術での読み上げはフェーズ5〜6の確認対象です。

## フェーズ2

`tests/unit/storage.test.ts`と`tests/unit/session.test.ts`で永続化・入力検証・保存の競合を、`tests/e2e/storage.spec.ts`でブラウザ操作を確認します。

| 対象 | 期待結果 |
| --- | --- |
| 一括登録 | PC・モバイルで画像24枚を登録し、複製後の25アイテムを再読込できる |
| 画像形式 | PNG・JPEG・WebP・GIFをデコードし、静止サムネイルを表示 |
| 読み込み方法 | ファイル選択、ファイルドロップ、画像貼り付けで未分類へ登録 |
| ファイル名 | 日本語と空白を保持し、拡張子を除いた名前でアイテムを作成 |
| 異常画像 | 空・破損・容量超過・寸法超過・拡張子不一致・MIME不一致を拒否 |
| 数量制限 | 100枚・100MiBの一括登録上限を検証 |
| プロジェクト | 作成・一覧・切り替え・複製・削除・削除キャンセル・最後の削除後の再作成 |
| 画像共有 | アイテム・プロジェクトの複製時にBlobを共有し、参照が残る画像を削除しない |
| 保存競合 | 保存中の追加編集を次に書き込み、別タブの新しいデータは上書きしない |
| 保存失敗 | 容量不足を再現し、トランザクションの取り消し、画面のデータ保持、バックアップ、再試行を確認 |
| 読込失敗 | IndexedDBの開始エラーを再現し、再試行後に既存の内容を読み込む |
| JSON往復 | 画像21枚を新規プロジェクトへ復元し、元画像のバイト列・配置・メタデータが一致 |
| 互換性 | projectとその内部の未知フィールドを保持し、未対応schemaVersionを拒否 |
| 不正JSON | 空・破損・容量超過・欠損フィールド・重複ID・不正配置・画像欠損・不正Base64・寸法偽装を拒否 |
| 復元失敗 | 既存プロジェクトを保持し、一部のBlobだけを保存しない |
| アクセシビリティ | プロジェクト一覧・画像登録ダイアログもaxeで検査 |

ファイル制限と容量不足の一部は、サイズ属性やIndexedDBの書き込みを差し替えて境界条件を再現します。端末のディスクを実際に使い切るテストは行いません。

## フェーズ3

`tests/unit/design.test.ts`で設定・適用範囲・旧データ互換性を、`tests/e2e/design.spec.ts`で表示・操作・保存復元を確認します。

| 対象 | 期待結果 |
| --- | --- |
| デザイン編集 | 背景・文字・画像サイズ・余白・枠・影・見出しの設定が表示と再読込に反映される |
| 個別寸法 | Tierの高さ・ラベル幅を保存でき、共通ラベル幅にも戻せる |
| テーマ | 全8種類でTier名・ID・配置・アイテムを保持し、ロック中の配色を変更しない |
| 適用範囲 | ランクのみ・カードのみでは、範囲外の設定を保持する |
| ランク配色 | Tier数が配色数を超えても名前・数・順序を維持する |
| 背景画像 | Blobを分離保存し、複製で共有した画像は最後の参照まで保持する |
| 切り抜き | 範囲外の入力を拒否し、表示の余白に切り抜き前の画素が出ない |
| EXIF | 回転付きJPEGを表示方向に沿って切り抜き、元ファイルを維持する |
| JSON往復 | 画像24枚・背景画像・切り抜き・設定・配置を新しいプロジェクトへ復元し、元画像のバイト列が一致する |
| 互換性 | フェーズ2のJSONと未知キーを保持し、不正な背景参照・切り抜き値を拒否する |
| 入力・エラー | 壊れた背景画像や不正値が保存済みデータを変更せず、入力破棄のキャンセルで下書きが残る |
| 表示幅 | 最大設定値でも320・768・1280・1920pxで意図しない横スクロールがない |
| アクセシビリティ | 全8テーマとデザインパネルをaxeのWCAG A/AAで検査する |

フェーズ1・2の操作テストも全件実行します。結果は[docs/verification-phase3.md](docs/verification-phase3.md)に記録します。

## フェーズ4以降

画像出力では形式、サイズ、倍率、透過、日本語ファイル名、文字化け、縦横比、空データ、長い表、編集用UIの除外を確認します。Undo・Redoはすべての編集操作を対象にします。PWAでは既存プロジェクトのオフライン編集を確認します。

画像出力、Undo・Redo、PWAは後続フェーズのため未検証です。実行結果はフェーズ1の`docs/verification.md`とフェーズ2の`docs/verification-phase2.md`に記録します。
